# Продолжение проекта в новой сессии

Состояние на 13 октября 2026.

## Цель и правила работы

Развернуть на Vast.ai личную студию фотореалистичных изображений и видео с
открытыми весами, ComfyUI, без платных API генерации. Пользователь хочет пройти
весь реальный флоу: промпт → изображение → видео → скачивание.
Нужны прогресс генерации, серверное хранение и восстановление галереи при входе.
Работать на русском, пошагово, подтверждать установку выводом/результатом,
диагностировать ошибки до исправлений, предупреждать о расходах, избегать простоя GPU.
Пользователь попросил выбрать базовый вариант и реализовать приложение с тестами.

## Что находится в архиве

Полный исходный код приложения Frame, README с командами, 14 тестов,
скрипты проверки GPU и загрузки моделей, ссылки на источники workflow.
Ключей API, паролей, весов моделей и пользовательских результатов нет.
Исходный локальный commit: e6ea0d7 (до добавления этой заметки).
Архив самодостаточен; доступ к старой сессии не нужен.

## Выбранная база

- Z-Image-Turbo: Text-to-Image, 8 шагов, 1024×1024 и прямоугольные форматы.
- Wan 2.2 TI2V-5B: Text-to-Video и Image-to-Video, 1280×704 / 704×1280,
  121 или 241 кадр при 24 fps (примерно 5/10 секунд).
- Экономичный кандидат: RTX 3090 24 ГБ, ≥64 ГБ RAM, ≥8 vCPU, SSD 200 ГБ.
  RTX 5090 32 ГБ — альтернативный вариант при приемлемой цене.
- Обычный официальный ComfyUI template Vast.ai. Конкретный образ ещё не выбран.
- Python aiohttp, SQLite, HTML/CSS/JS без сборки. Постоянная панель рассчитана
  на небольшой VPS, а генерация — на подключаемый Vast GPU.
- Другие модели не устанавливать до успешного теста этой пары.

## Что реализовано и проверено

- Последовательная серверная очередь, прогресс из WebSocket ComfyUI.
- Галерея и скачивание, загрузка исходного изображения, кнопка «Оживить».
- Сохранение параметров, seed и API-workflow каждого задания.
- Восстановление истории и отслеживания prompt_id после перезапуска приложения.
- Идемпотентная отправка; неопределённо отправленные задания не запускаются снова.
- Пароль, CSRF-защита, проверка типов/размеров изображений, блокировка второго worker.
- Управление Vast: список, поиск предложений, start/stop, rent/destroy с подтверждением.
- Docker Compose, Caddy HTTPS, CI и ручной GitHub Actions deploy на VPS.
- 14 unittest-тестов прошли, node --check и compileall прошли.

Тесты используют имитацию HTTP/WebSocket ComfyUI, не GPU.
Реальная совместимость графов/весов, генерация, VRAM, скорость, качество,
браузерная визуальная проверка и публичный HTTPS-доступ НЕ подтверждены.
GPU не арендован, модели не скачаны, расходов этой сессией не запущено.
Исходный кадр и результаты хранятся на локальном диске инстанса; это не backup.
Закрытие браузера не мешает работе, но Stop останавливает GPU, а Destroy может удалить файлы.

## Vast.ai — точная диагностика, не считать ключ недействительным

Ключ предоставлялся в старой сессии, но намеренно НЕ включён в архив.
Передавался без искажений: 64 символа, без пробелов; заголовок Authorization: Bearer.
Сначала использовали /api/v0/instances/, затем перепроверили по официальному
CLI и документации актуальный GET https://console.vast.ai/api/v1/instances.
Второй запрос вернул HTTP 401 с текстом:

> Authorization Error. Your key lacks proper privileges to perform this action as it requires you to have logged in using Two Factor Authentication

Это сообщение о требованиях авторизации/2FA, а не доказательство ошибочного ключа.
Последнее сообщение пользователя: он уже изменил настройки, у него всё работает,
и он считает, что проблема именно в старой сессии. Это сообщение пользователя;
после изменения настройки инструментами повторно не проверены.
Не требовать повторения уже выполненной настройки: сначала проверить доступ в новой сессии.

Документация: https://docs.vast.ai/api-reference/instances/show-instances
Официальный CLI: https://github.com/vast-ai/vast-python
Не передавать ключ в URL, Git, клиентский JS, логи или этот архив.
Запросить доступ к секрету заново безопасным способом, если он недоступен в новой сессии.

## Следующие шаги для помощника

1. Проверить GitHub Actions CI после отправки кода.
2. Поднять постоянную панель на VPS по разделу README, создать серверный `.env`.
3. Проверить Vast read-only запросом /api/v1/instances через интерфейс с действующим ключом.
   Учесть, что пользователь уже исправлял настройки.
4. Проверить текущие on-demand предложения и полную стоимость диска/трафика,
   совместимость Docker tag и драйвера. Предупредить о цене до начала аренды.
5. Развернуть ComfyUI на выбранном GPU и безопасно связать его с панелью. Примерные пути официального образа:
   /workspace/ComfyUI, /venv/main/bin/python, ComfyUI internal port 18188.
   Подтвердить их на сервере. Studio по run.sh: 127.0.0.1:8090.
6. Запустить scripts/check_environment.py интерпретатором ComfyUI.
   Зафиксировать реальные версии/commit; отдельный venv для веб-приложения.
7. Скачать только Z-Image комплект, запустить реальное изображение,
   проверить прогресс, файл, скачивание и восстановление галереи.
8. Только затем Wan 5B: T2V 5 секунд и I2V с созданным кадром.
9. Зафиксировать время/VRAM/стоимость, обеспечить повторный запуск и защиту HTTPS.

Минимальная локальная проверка (не запускает аренду или загрузку весов):

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
node --check studio/static/app.js
```
