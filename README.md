# Frame — AI Content Generation

Личная веб-студия поверх **локального ComfyUI на Vast.ai**.
Без платных API генерации. Интерфейс и история работают на сервере.

## Что готово

- Изображение из промпта: Z-Image-Turbo, 8 шагов.
- Видео из текста или исходного изображения: Wan 2.2 TI2V-5B.
- 720p-класс видео (1280×704 или 704×1280), примерно 5/10 секунд.
- Выбор формата и seed; кнопка «Оживить» у готового изображения.
- Последовательная серверная очередь, максимум 10 незавершённых заданий.
- Настоящие события прогресса ComfyUI; процент относится к текущему этапу.
- Галерея, скачивание файлов и API-workflow, повтор параметров.
- SQLite + файлы на диске: история возвращается при открытии страницы.
- Переподключение к ComfyUI и восстановление задания по prompt_id.
- Защита от дублей при повторной отправке, отсутствие автоматического перезапуска
  неопределённо отправленного задания, блокировка второго worker для той же БД.
- Пароль на интерфейс/API/файлы, защита от CSRF, ограничение входных изображений.
- Панель Vast.ai: список серверов, поиск verified/on-demand предложений,
  запуск, остановка, аренда и удаление с явным текстовым подтверждением.
- Адаптивный интерфейс для телефона и готовый Docker-деплой с HTTPS.

**Статус:** приложение проверено интеграционными тестами с имитацией HTTP/WebSocket
ComfyUI. Реальная генерация, VRAM, скорость и качество на GPU пока не проверены.
Имитация существует только в тестах; приложение никогда не подменяет результат
генерации демонстрационной картинкой.

## Базовая конфигурация

Начальный экономичный вариант: 1× RTX 3090 24 ГБ, ≥64 ГБ выделенной RAM,
≥8 vCPU, 200 ГБ SSD, on-demand, verified host. RTX 5090 32 ГБ — вариант
для более быстрого интерактивного тестирования при подходящей цене.
Реальные минимумы зависят от длительности, разрешения и offload. Начинайте
с изображения, затем 5-секундного видео; 10 секунд могут потребовать больше памяти.

Используйте **официальный ComfyUI template Vast.ai**. Подробности:
https://github.com/vast-ai/base-image/tree/main/derivatives/pytorch/derivatives/comfyui

В этом семействе образов ComfyUI обычно находится в `/workspace/ComfyUI`, Python —
`/venv/main/bin/python`, внутренний порт ComfyUI — `18188`. Сначала проверьте
реальные пути выбранного образа. Не заменяйте рабочий PyTorch вслепую.
Точный Docker tag следует выбрать в консоли и записать вместе с отчётом окружения.
Для RTX 5090 необходима сборка PyTorch с поддержкой sm_120 / CUDA 12.8+.

## 1. Проверка окружения — на GPU-сервере

После того как проект скопирован в `/workspace/ai-content-generation`:

```bash
cd /workspace/ai-content-generation
/venv/main/bin/python scripts/check_environment.py \
  --comfy-dir /workspace/ComfyUI \
  --comfy-url http://127.0.0.1:18188 > runtime-report.json
cat runtime-report.json
```

Скрипт выполняет настоящее CUDA-умножение матриц, фиксирует версии Python/PyTorch,
CUDA runtime, GPU/VRAM, свободный диск, commit ComfyUI и ответ `/system_stats`.
Если пути отличаются — подставьте подтверждённые пути из шаблона.

## 2. Приложение в отдельном venv

Требуется Linux, Python 3.12. Отдельное окружение не меняет зависимости ComfyUI.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Зафиксированные зависимости приложения: aiohttp 3.14.4, Pillow 12.3.0.

## 3. Первая модель — только изображения

Сначала посмотреть объём и доступность, затем загрузить:

```bash
.venv/bin/python scripts/download_models.py --comfy-dir /workspace/ComfyUI --model image
.venv/bin/python scripts/download_models.py --comfy-dir /workspace/ComfyUI --model image --download
```

Скрипт получает ревизию и SHA256 из Hugging Face, скачивает только три нужных
компонента, проверяет размер/хеш и сохраняет manifest ревизий. Проверенные
существующие файлы не скачиваются повторно. Несовпадающий файл автоматически
не перезаписывается. После прерванной загрузки `.part` скачивается заново.
Загрузка весов использует оплачиваемый трафик и время GPU-инстанса.

## 4. Запуск и доступ на GPU для первого теста

Введите отдельный пароль студии. Для локального теста на одном GPU-сервере
Vast API key приложению не нужен.

```bash
read -rs -p 'Пароль студии (не менее 16 символов): ' STUDIO_PASSWORD
export STUDIO_PASSWORD
bash scripts/run.sh
```

По умолчанию приложение слушает `127.0.0.1:8090`, использует
`COMFY_URL=http://127.0.0.1:18188`, данные пишет в `/workspace/studio-data`.
Логин браузера: `studio`; пароль — введённый выше.

Первый безопасный доступ — SSH-туннель. На своём компьютере используйте
**точные SSH host/port из карточки Vast**, добавив `-L 8090:127.0.0.1:8090`.
После этого откройте http://127.0.0.1:8090 .
Не публикуйте HTTP Basic Auth и ComfyUI напрямую в интернет без TLS и защиты.
Для постоянного браузерного адреса настройте HTTPS reverse proxy или защищённый
Vast Instance Portal. Это отдельный шаг после подтверждённого GPU-теста.

Для постоянной работы добавьте `bash scripts/run.sh` в Supervisor выбранного
образа с рабочей папкой проекта, переменными `STUDIO_*` и `autorestart=true`.
Секрет передавайте через защищённое окружение сервиса, не Git.
Не запускайте приложение с `--reload` или несколькими workers.

## Постоянная панель управления и Vast.ai

Если интерфейс запущен на самом GPU, после Stop пропадёт и кнопка Start. Поэтому
для постоянной панели используйте отдельный недорогой VPS, а Vast-инстанс оставьте
только вычислительным узлом. Скопируйте пример окружения и заполните секреты:

```bash
cp .env.example .env
chmod 600 .env
docker compose up -d --build
```

Обязательны `STUDIO_PASSWORD`, `VAST_API_KEY` и доступный с VPS `COMFY_URL`.
Ключ Vast хранится только в `.env` на сервере; браузер его не получает. Для
однокнопочной аренды желательно указать `VAST_TEMPLATE_ID` созданного в Vast
шаблона ComfyUI. Без него используется `VAST_IMAGE`, однако параметры портов и
запуска всё равно должны соответствовать вашему образу.

Для публичного адреса задайте `STUDIO_DOMAIN`, направьте DNS A/AAAA на VPS и
запустите:

```bash
docker compose -f docker-compose.production.yml up -d --build
```

Caddy автоматически получает TLS-сертификат. Не публикуйте эту панель без HTTPS:
она защищена HTTP Basic Auth. Для связи VPS с ComfyUI предпочтителен приватный
туннель (например, WireGuard/Tailscale); альтернативно задайте защищённый внешний
URL и `COMFY_AUTHORIZATION`.

GitHub Actions `CI` запускает тесты на каждый push/PR. Workflow
`Deploy control panel` для домашнего сервера использует отдельный self-hosted runner
с меткой `frame-prod`. Runner сам устанавливает исходящее соединение с GitHub;
входящий SSH и публичный порт для деплоя не нужны. После регистрации runner
создайте repository variable `ENABLE_DEPLOY=true` в GitHub → Settings →
Secrets and variables → Actions. Успешный CI после push в `main` обновляет
чистую Git-копию до проверенного commit и выполняет `docker compose up -d --build`.
Workflow можно запустить вручную. Серверный `.env` и Docker volume не перезаписываются.
Деплой прекращается при локальных изменениях отслеживаемых файлов.

## 5. Видео после успешного изображения

```bash
.venv/bin/python scripts/download_models.py --comfy-dir /workspace/ComfyUI --model video
.venv/bin/python scripts/download_models.py --comfy-dir /workspace/ComfyUI --model video --download
```

Выберите «Видео из текста» или нажмите «Оживить» на изображении. Начните с 5 секунд.
Прогресс может отсутствовать при загрузке весов/декодировании — тогда отображается
этап, а не выдуманный процент. Завершение отмечается только после ответа ComfyUI
и успешного сохранения файла. При OOM карточка покажет ошибку; авто-повтора нет.

## Данные и повторный запуск

```
/workspace/studio-data/
  studio.sqlite3       # история, очередь, параметры
  files/               # исходные изображения и результаты
  workflows/           # API JSON отправленных заданий
```

Модели остаются в `ComfyUI/models/`. ComfyUI также сохраняет собственные outputs;
студия копирует результат в своё хранилище для независимости от очистки history.
Это расходует дополнительное место. Автоматического удаления данных нет.

Закрытие страницы не останавливает очередь. Перезапуск **приложения** восстанавливает
подключение к активному prompt_id. Перезапуск **ComfyUI/инстанса** не возобновляет
диффузию с того же шага: потерянное задание помечается ошибкой, его можно повторить.

Stop инстанса продолжает тарификацию диска; Destroy может удалить данные.
Хранилище локально конкретному серверу, не является резервной копией.
Перед удалением инстанса скачайте результаты и сохраните `/workspace/studio-data`.
Для согласованной резервной копии остановите Studio и скопируйте всю папку данных,
включая SQLite WAL/SHM, если они остались.

## Тесты

```bash
python -m unittest discover -s tests -v
node --check studio/static/app.js
```

Тесты проверяют HTTP→очередь→WebSocket progress→history→файл→скачивание,
перезапуск приложения, идемпотентность, ошибки ComfyUI, авторизацию/CSRF,
загрузку изображений и T2V/I2V-протокол. Они не измеряют качество или скорость GPU
и не доказывают совместимость весов с конкретным сервером.

Браузерная визуальная проверка пока не выполнена. Интерфейс адаптивный, русский,
без внешних CDN и клиентских секретов. Базовый выпуск однопользовательский;
img2img и обучение LoRA в него не входят. Аренда через интерфейс создаёт платный
ресурс и требует ручного ввода `RENT <offer_id>`; Destroy требует
`DESTROY <instance_id>`.

## Архитектура

`браузер → HTTPS/Caddy → aiohttp Studio → ComfyUI HTTP/WebSocket → GPU`

`studio/server.py` — защищённые маршруты; `store.py` — SQLite;
`comfy.py` — очередь, события и сохранение; `workflows.py` — API-графы;
`static/` — интерфейс без сборщика. Источники workflow — в `workflows/SOURCES.md`.

Ключи Vast/Hugging Face, пароли, модели, результаты и БД не должны попадать в Git.
